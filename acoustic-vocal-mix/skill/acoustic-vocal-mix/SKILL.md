# Сведение «голос + акустика» с замерами вместо ушей

У тебя нет ушей. Есть три источника правды:
1. **Замеры** скриптами из `scripts/` (числа, таблицы, PNG-графики; графики открывай и смотри).
2. **Референсы**: 3–5 готовых песен того же жанра. Без референса «правильный звук» не определён.
3. **Уши пользователя** на контрольных точках. Никогда не говори «звучит отлично». Говори «по замерам…» и проси послушать.

## Три режима работы

| режим | когда | как |
|---|---|---|
| **A. Офлайн-движок** (основной) | всегда, когда есть экспорт стемов | `mix_engine.py render config.json --analyze`: рендер за секунды, точные значения, версии, сравнение |
| **B. Cubase через computer use** | перенос готовых настроек в проект, финальная доводка, если пользователь хочет всё внутри Cubase | см. `references/cubase-computer-use.md`. Скриншоты нужны, чтобы **крутить ручки**, а не чтобы **слушать** |
| **C. Только анализ** | пользователь сводит сам | экспорт стемов или микса, потом `mix_analyzer.py analyze`, потом советы по приоритету |

Скриншот показывает момент, а не процесс. Каждую секунду ты не смотришь. Для оценки звука экспортируй и меряй. По скриншоту читай только **интегральные** показатели (Integrated LUFS, LRA, max TP) после проигрывания всего фрагмента.

## Установка (один раз)

```bash
pip install -r scripts/requirements.txt
python scripts/mix_analyzer.py selftest              # должно быть OK
python scripts/mix_engine.py list-plugins -v          # какие VST3 есть у пользователя
python scripts/mix_engine.py params "<путь к .vst3>" --filter freq   # имена параметров плагина
```
Waves лежат в контейнере WaveShell. Укажи `--name "CLA-76 Stereo"` (точное имя смотри в `list-plugins -v`). Если плагин не грузится в pedalboard (защита, оболочка), используй встроенный аналог движка и перенеси настройку в Cubase руками или через computer use.

## Пайплайн

**0. Задача.** Спроси (или возьми из контекста): темп (BPM), настроение, 3–5 референсов. Если у пользователя Cubase 15, предложи разделить референсы на стемы (Stem Separation) или через UVR/Demucs. Тогда будут `--ref-vocal` и `--ref-guitar`, и цели станут точными (например, на сколько LU вокал выше гитары именно в этом жанре).

**1. Экспорт.** Cubase: File → Export → Audio Mixdown → Channel Batch Export, WAV 24 бит (или 32 float), та же частота, что у проекта, все стемы от начала проекта (одинаковое начало обязательно для маскировки и выравнивания). Для анализа «сырых» дорожек отключи инсерты или экспортируй исходные клипы.

**2. Анализ сырья.**
```bash
python scripts/mix_analyzer.py analyze --stage raw --vocal vocal.wav --guitar gtr_di.wav --guitar gtr_mic.wav \
  --ref ref1.wav --ref ref2.wav [--ref-vocal rv1.wav --ref-guitar rg1.wav] --out analysis/raw --spectrogram
```
Сначала чини запись: клиппинг, фон, шум, неровный уровень входа. Клиппинг лечится перезаписью, а не плагином. Если есть DI и микрофон гитары, запусти `align` и при желании `make-ir` (см. `references/acoustic-guitar-chain.md`).

**3. Конфиг v1.** Скопируй `scripts/mix_config.example.json` и собери цепочки по рецептам из `references/vocal-chain.md` и `references/acoustic-guitar-chain.md`. Стартовые значения бери из `references/targets.md`. Реальные плагины пользователя (`"type": "vst3"`) используй там, где они грузятся. Сначала выясни имена параметров командой `params`.

**4. Цикл «изменил → измерил»:**
```bash
python scripts/mix_engine.py render mix.json --label v2 --analyze --previous renders/v1/analysis/report.json
```
- Читай `renders/vN/analysis/report.md` сверху вниз: сначала [СИЛЬНО], потом [средне]. Смотри `profile_*.png` и `masking.png`.
- За одну итерацию меняй **одну стадию** (чистка → EQ → динамика → баланс → пространство → шина), иначе не поймёшь, что сработало.
- Таблица «Что изменилось с прошлого прогона» подтверждает, что правка дала нужный эффект и ничего не сломала.
- Критерии остановки: нет [СИЛЬНО]; широкие полосы в пределах ±2 dB от референса (кроме осознанных решений); `vocal_over_guitar` в пределах ±1.5 LU от референса; ровность вокала 4–8 LU; сибилянты не выше референса; маскировка 1–4 кГц ≤ −3 dB; корреляция микса > 0.3.
- 6–8 итераций без прогресса означают: остановись и попроси пользователя послушать.

**5. Контрольная точка с пользователем.** Дай `mix.wav`, кратко скажи, что поменял и почему (с цифрами), и попроси описать звук словами. Переводи слова в действия по глоссарию ниже.

**6. Перенос в Cubase.** В `renders/vN/` лежат `cubase_recipe.md` и `presets/*.vstpreset`. Либо пользователь переносит сам по рецепту, либо ты через computer use по протоколу из `references/cubase-computer-use.md`. Встроенные процессоры движка (de-esser, spectral_duck, сатурация) в Cubase заменяются плагинами, указанными в рецепте.

**7. Мастер** отдельным шагом: `--master master.wav --stage master --target-lufs -14`. Цели в `references/targets.md`.

## Глоссарий: слова пользователя → частоты

| говорит | где искать | что делать |
|---|---|---|
| бубнит, гудит, «в бочке» | 120–300 Гц | срез колоколом −2..−4 dB / динамическая полоса |
| коробка, картон, «из ведра» | 300–700 Гц | срез −2..−3 dB, Q 1–2 |
| в нос, гнусаво; у гитары «пластик, кряк» | 800 Гц–2.5 кГц | узкий/динамический срез, soothe2, IR тела |
| режет, колет, утомляет | 2.5–5 кГц | динамический срез, soothe2, меньше компрессии с быстрой атакой |
| шипит, свистит, «эсы» | 5–9 кГц | де-эссер, отдельный де-эссер на посыл ревера |
| глухо, тускло, «под одеялом» | 3–12 кГц не хватает | полка +1.5..+3 dB на 10–12 кГц, сатурация, меньше LPF |
| тонко, худо | 100–250 Гц не хватает | ниже HPF, +1..+2 dB на 150–200 Гц |
| далеко, утоплен (вокал) | баланс, присутствие, ревер | +1..+3 dB фейдером, +1..+2 dB на 3–5 кГц, меньше посыла / больше pre-delay |
| мокро, каша | ревер/дилей | короче decay, HPF/LPF на возвратах, дакинг дилея |
| плоско, без жизни | динамика | меньше лимитирования, параллельная компрессия, сатурация, автоматизация |

## Правила безопасности

- Исходники пользователя только читай. Пиши в `renders/vN/` и `analysis/`. Ничего не перезаписывай.
- В Cubase перед изменениями делай File → Save New Version. Не удаляй треки и клипы. Не применяй деструктивную обработку (Direct Offline Processing, Render in Place) без явного «да».
- Если замеры и уши пользователя расходятся, права уши пользователя. Найди, какую метрику они опровергают, и запиши это в отчёт.
- Цифры в `targets.md` служат стартовыми ориентирами. Если есть референс, он важнее таблицы.

## Справочники (читай по необходимости)

- `references/targets.md`: числа и диапазоны (запись, уровни, компрессия, ревер, дилей, баланс, мастер).
- `references/vocal-chain.md`: цепочка вокала: чистка, тюнинг, EQ, серия компрессоров, де-эссер, сатурация, посылы, автоматизация.
- `references/acoustic-guitar-chain.md`: Cort AD810E (пьезо, преамп CE304T), запись DI + микрофон, фаза, IR, EQ-карта пьезо, компрессия, стерео, расчистка под голос.
- `references/cubase-computer-use.md`: экран, плагины-измерители для скриншотов, протокол кликов, перенос пресетов, MIDI Remote.
- `references/plugins.md`: карта задач → плагины пользователя (FabFilter / Valhalla / Waves) и что докупить.
- `references/engineering-library.md`: принципы топовых инженеров, источники и протокол пополнения библиотеки.

## Скрипты

| команда | что даёт |
|---|---|
| `mix_analyzer.py analyze …` | `report.md` (что исправить, по приоритету), `report.json`, PNG графики |
| `mix_analyzer.py align A.wav B.wav` | сдвиг (мс и сэмплы) и полярность второй записи относительно первой |
| `mix_analyzer.py make-ir --di DI.wav --mic MIC.wav --out ir.wav` | IR «пьезо → микрофон» именно этой гитары + график коррекции |
| `mix_analyzer.py selftest` | проверка измерителя громкости по эталону EBU |
| `mix_engine.py render cfg.json --analyze [--previous …]` | микс, стемы, `.vstpreset`, `cubase_recipe.md`, отчёт |
| `mix_engine.py list-plugins -v` / `params PATH [--name] [--filter]` | плагины и их параметры |

Типы инсертов движка: `hpf`, `lpf` (Butterworth, `slope_db_oct` 6–48), `peak`, `lowshelf`, `highshelf`, `comp` (+`makeup_db`), `limiter`, `gain`, `reverb`, `delay` (`bpm` + `note`: `1/4`, `1/8d`, `1/8t`), `ir` (свёртка), `deesser` (`relative_db`: потолок эсов относительно гласных), `spectral_duck` (`key`: имя трека-ключа, `f_lo`/`f_hi`/`depth_db`), `saturate`, `vst3` (`path`, `plugin_name`, `params`, `preset`). Поля трека: `file`, `role` (`vocal`/`guitar`), `clip_gain_db`, `delay_samples`/`delay_ms`, `invert`, `inserts`, `fader_db`, `pan` (−1..1), `width`, `sends` {bus: dB}, `mute`. У любого инсерта есть `bypass`.
